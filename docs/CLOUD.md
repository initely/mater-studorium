# Перенос работы в облачные сессии Claude Code (claude.ai/code)

Цель: вести проект из браузера или с телефона, не держа компьютер включённым. Облачная сессия каждый раз стартует со свежего клона репозитория, поэтому всё нужное лежит в репозитории: `CLAUDE.md`, `TASKS.md`, `tools/cloud/`, `.claude/settings.json`.

Источники по облачной среде: документация Anthropic «Use Claude Code in the cloud» и «Configure cloud environments» (code.claude.com). Условия и лимиты со временем меняются: если что-то разойдётся с этим файлом, верьте документации.

## 1. Что в облаке работает, а что нет

| Что нужно проекту | В облачной VM | Решение |
|---|---|---|
| Ubuntu 24.04, x86_64, 4 vCPU, 16 ГБ RAM, 30 ГБ диска, root | есть | достаточно; полный `supabase start` (десяток контейнеров) и Flutter помещаются, но 30 ГБ диска не безграничны: `docker system prune` при нехватке |
| Docker (`docker`, `dockerd`, `docker compose`) | есть по документации | нужен локальному Supabase; хук `session-start.sh` пробует поднять демон, если он не запущен (не проверено на живом облаке, см. раздел 7) |
| Flutter 3.47.2 + Dart | **нет** | `tools/cloud/setup.sh` ставит из `storage.googleapis.com` (домен разрешён в Trusted) |
| Deno 2.9.7 | **нет** | `setup.sh` ставит бинарник из GitHub Releases |
| Supabase CLI 2.120.0 | **нет** | `setup.sh` ставит из GitHub Releases с проверкой контрольной суммы |
| образы Supabase (`public.ecr.aws`, `ghcr.io`) | домены разрешены в Trusted | первый `supabase start` скачивает образы (несколько минут); образы, скачанные в setup-скрипте, попали бы в кэш окружения, но скрипт тогда не уложится в 5 минут, поэтому не качаем заранее |
| pub.dev, Maven/Gradle (Google, Central) | разрешены | `flutter pub get` работает |
| Android SDK, сборка APK, эмулятор, реальное устройство | **нет** (`dl.google.com` не в списке разрешённых, SDK не установлен) | APK собирайте локально или позже отдельным workflow GitHub Actions; в облаке: тесты, analyze, `flutter build web`, всё серверное |
| `openrouter.ai` (живые вызовы оценки ответов) | **не разрешён** по умолчанию | только для живых проверок: уровень сети Custom + домен `openrouter.ai`; обычные тесты сеть не используют |
| Облачный Supabase, Firebase, Google Cloud (деплой) | `supabase.com`/`supabase.co` не в списке | деплой делать **с вашей машины**, не из облачной сессии |
| Диктовка, напоминания, TalkBack, внешний вид | нет устройства и GUI | ручные проверки на вашем телефоне (`docs/USER_TODO.md`, раздел 1) |
| Локальные пути | нет привязки | в репозитории нет путей `/home/...`; Dart и Deno в облаке доступны как `dart` и `deno` из `/usr/local/bin` |

Вывод: **в облаке можно делать почти всю разработку и ревью** (код Flutter, миграции, pgTAP, Edge Functions, гонки, Opus-ревью безопасности). Нельзя: сборка APK и всё, что требует вашего телефона, облачных проектов и ключей.

## 2. Что проверено при подготовке

- Секреты: в отслеживаемых файлах и во всей истории git (все ветки) ключей нет; `.env`, `.env.json`, `.env.openrouter`, `supabase/.env` игнорируются. В `.gitignore` добавлены `*.jks`, `*.keystore`, `*.pem`, `*.p12`, `google-services.json`, сервисные аккаунты Firebase.
- Пути: в отслеживаемых файлах нет абсолютных путей к вашему домашнему каталогу.
- Размер репозитория 13 МБ (ограничение bundle 100 МБ не мешает).
- Версии инструментов: `tools/cloud/check_versions.sh` сравнивает `setup.sh` с `ci.yml`.
- Setup-скрипт прогнан на чистом образе `ubuntu:24.04` в Docker: см. раздел 7 (результат и время).

## 3. Создание окружения

В claude.ai/code: окружение (Environment) → создать.

1. **Название:** `mater-studorium`.
2. **Сеть:** `Trusted` достаточно для разработки и тестов. Для живых вызовов оценки ответов: `Custom`, включить стандартные домены и добавить `openrouter.ai`. Уровень `None` не подходит (установка пакетов невозможна). Уровень `Full` не нужен.
3. **Переменные окружения:** по умолчанию **никаких**. Всё нужное для локальных тестов (демо-ключи Supabase) генерирует `supabase start`. Список опциональных переменных в разделе 5.
4. **Setup script:** вставьте полное содержимое файла `tools/cloud/setup.sh` (оно не зависит от клонирования репозитория). Скрипт идемпотентен, выходит с кодом 0, ставит всё параллельно.
5. Сохраните. При первом запуске сессии скрипт выполнится, и если уложится примерно в 5 минут, окружение закэшируется (повторно раз в ~7 дней или при смене скрипта и разрешённых доменов).

В репозитории уже лежит `.claude/settings.json` с SessionStart-хуком: в облаке (`CLAUDE_CODE_REMOTE=true`) он выполнит `tools/cloud/session-start.sh` (дозапуск setup при отсутствии инструментов, `flutter pub get`, docker-демон), локально не делает ничего.

## 4. GitHub: подготовка и перенос

Сейчас репозиторий только на вашем компьютере (39+ коммитов, ветка `main`, remote нет). Пока вы не подтвердите, я ничего не пушу.

Какие ветки переносить: только **`main`** и **`t23-duel-play`** (незаконченное ревью T23). Остальные ветки `worktree-agent-*` служебные и уже слиты, их пушить не нужно.

Шаги руками:

1. На github.com создайте **пустой приватный** репозиторий (без README, `.gitignore` и лицензии), например `mater-studorium`.
2. Авторизация на компьютере, если ещё нет: `gh auth login` (GitHub CLI, выбрать HTTPS и браузер) или создать personal access token (fine-grained, права Contents: Read and write на этот репозиторий) и использовать его как пароль при `git push` по HTTPS.
3. Подключение (команды выполните вы или скажите мне «пушь»):
   ```
   git remote add origin https://github.com/<ваш-логин>/mater-studorium.git
   git push -u origin main
   git push -u origin t23-duel-play
   ```
4. Проверьте на странице репозитория, что нет `.env*`, ключей и `build/`. Перед тем как открывать репозиторий публично, просканируйте историю (gitleaks), сейчас он приватный.
5. На claude.ai подключите GitHub: онбординг claude.ai/code (установка Claude GitHub App на репозиторий) или `/web-setup` в терминале (отправляет токен `gh` в аккаунт Claude). GitHub App нужен ещё и для Auto-fix PR.
6. Включите Actions в репозитории: ни один workflow ещё не запускался по-настоящему; первый запуск CI покажет, что чинить (пришлите вывод упавших шагов).

Запасной путь без GitHub: `claude --cloud "..."` из каталога проекта загружает локальный репозиторий в сессию bundle-ом (до 100 МБ, без неотслеживаемых файлов), но результат тогда нельзя запушить обратно. Для постоянной работы нужен GitHub.

## 5. Секреты и переменные окружения

| Переменная | Обязательна | Зачем | Замечание |
|---|---|---|---|
| (нет) | нет | тесты, `supabase start`, pgTAP, deno, analyze: всё работает без секретов | локальные ключи Supabase демонстрационные и публичные |
| `OPENROUTER_API_KEY` | только для живых проверок оценки ответов | живой прогон `grade-open-answer` и eval | использовать **отдельный ключ с жёстким кредитным лимитом**; переменные окружения видны всем, кто пользуется окружением; на Pro/Max есть «network secrets», которые подставляются прокси и не попадают в песочницу (проверьте в настройках окружения) |
| ключи Supabase облака (service role), Google OAuth, Firebase, keystore | **не задавать** в облачном окружении | деплой и подпись делаются с вашей машины | в облако не нужны |

Правило проекта: секреты никогда не попадают в клиент и в git (`CLAUDE.md`, правило №6).

## 6. Что мешает облаку, но не критично

- **Автопилот и отложенные пробуждения.** Облачные сессии останавливаются после простоя, а ожидающие `ScheduleWakeup` самонастраиваемого `/loop` после истечения окружения **не восстанавливаются** (нужно запустить `/loop` заново). Для долгих цепочек задач лучше ставить один промпт на одну задачу и перезапускать по мере надобности.
- **Лимиты.** Облачные сессии делят лимит аккаунта с остальным использованием Claude; параллельные агенты расходуют его быстрее. Держите одного исполнителя за раз.
- **Слияния и push.** Облачная сессия пушит ветки (обычно с префиксом `claude/`) и открывает PR; слияние в `main` вы делаете на GitHub. Локальная схема «слить в main без push» в облаке заменяется работой через ветки и PR.
- **Один локальный Supabase на VM.** В одной облачной сессии по-прежнему не запускайте два агента, которым нужен `supabase start`.
