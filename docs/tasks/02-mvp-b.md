# MVP-b. Дополнительные форматы (T27–T30)

Начинать только после того, как MVP-a прошёл чек-лист T26 и вы пользовались им ≥ 1 неделю.

Общий шаблон каждой задачи:
- грейдер — чистая функция в `features/grading/domain/` со 100% покрытием веток;
- виджет — в `features/questions/<type>/`, регистрируется в `registry.dart`;
- код сессии не меняется (это проверка того, что реестр спроектирован правильно; если менять пришлось, зафиксировать почему);
- черновики контента из T25 этого типа вычитаны → `approved` → новая версия колоды импортирована.

## T27. Формат `cloze` (заполни пропуск)
- **Цель:** US12, точное вспоминание терминов без LLM.
- **Входы:** ТЗ §4.3 (`cloze`), §7.1 (payload), M4.
- **Сделать:**
  1. Грейдер:
     - нормализация (lower, trim, `ё` → `е`, пробелы, пунктуация по краям);
     - сравнение с `accepted[]`;
     - Левенштейн ≤ 1 при длине ≥ 6 означает «принято с опечаткой» и Hard;
     - числа сравниваются как числа;
     - вердикт по каждому пропуску.
  2. Виджет: текст с инлайн-полями (`{{id}}` → `TextField`), переход фокуса между пропусками, отправка по Enter. Подсветка каждого пропуска после ответа и показ принятого варианта.
- **Критерии приёмки:** unit-тесты грейдера (≥ 12 кейсов: регистр, ё, опечатка на коротком и длинном слове, число «443» против «443.0», несколько пропусков); widget-тест; масштаб текста 200% без переполнения.
- **Проверка:** тесты + ручной прогон.
- **Зависимости:** T26. **Размер:** S–M.
- **Модель:** Sonnet.

## T28. Формат `order` (порядок шагов)
- **Цель:** US12, процессы (TLS handshake, kill chain, реагирование на инцидент).
- **Входы:** ТЗ §4.3 (`order`), M4, AC4.3.
- **Сделать:**
  1. Перемешивание с seed, гарантированно не совпадающее с эталоном.
  2. Грейдер: полное совпадение → Good; ровно одна перестановка соседних → Hard; иначе Again. Позиции каждого шага для подсветки.
  3. Виджет: `ReorderableListView` + кнопки ↑↓ у каждого шага (доступность и web) + «Проверить». После ответа: верные позиции зелёные, неверные помечены и показывают правильный номер.
- **Критерии приёмки:** AC4.3; unit-тесты грейдера; widget-тест перестановки кнопками.
- **Проверка:** тесты + ручной прогон на Android (drag) и web (drag и кнопки).
- **Зависимости:** T26. **Размер:** S–M.
- **Модель:** Sonnet.

## T29. Формат `find_error` (найди ошибку)
- **Цель:** US12, конфиги, код и утверждения с ошибкой.
- **Входы:** ТЗ §4.3 (`find_error`), §7.1 (payload), M4.
- **Сделать:**
  1. Грейдер: совпадение множеств выбранных строк и `error_lines`.
  2. Виджет:
     - `mode = code`: моноширинный шрифт, номера строк, горизонтальный скролл (без переноса), подсветка синтаксиса по желанию [проверить лёгкий пакет; без него ок];
     - `mode = text`: список утверждений;
     - тап выделяет строку, до 2 выделений;
     - «Проверить».
  3. После ответа: ошибочные строки помечены, у каждой показывается `line_explanations[n]`.
  4. Semantics: «строка 3: <текст>, выбрана».
- **Критерии приёмки:** unit-тесты грейдера; widget-тесты для обоих режимов; длинная строка не ломает разметку на узком экране (360 dp).
- **Проверка:** тесты + ручной прогон.
- **Зависимости:** T26. **Размер:** M.
- **Модель:** Sonnet.

  2. Вычитать черновики новых форматов из T25 и импортировать новую версию колоды.

- **Критерии приёмки:** чек-лист пройден; в колоде ≥ 15 approved вопросов каждого нового формата.
- **Проверка:** ручная по чек-листу.
- **Зависимости:** T27–T29. **Размер:** M.
- **Модель:** Sonnet.
