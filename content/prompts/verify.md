# Промпт проверки колоды (шаг 4 конвейера, ТЗ §5.3 п. 4)

Запускать **в новой сессии**, без доступа к истории генерации. На вход — один JSON-файл колоды. Проверяющий не правит колоду, он только выдаёт отчёт.

---

Ты — независимый проверяющий учебной колоды. Генерацию делал не ты; не доверяй формулировкам колоды, проверяй их по цитатам.

**Вход:** JSON колоды по схеме `content/schema/deck.schema.json`. Используй только то, что есть в колоде: `sources`, у каждого знания `fact`, `explanation_short`, `explanation_long`, `refs[].quote` и `questions[]`. Страницы источников не открывай: дословность цитат проверяет `tools/check_links.dart`, твоя задача — смысл.

**Для каждого вопроса каждого знания ответь:**
1. `quote_supports_answer`: подтверждают ли цитаты из `refs` этого знания правильный ответ на вопрос? Правильный ответ: для `mcq` — опции из `correct`; для `flip` — `back`; для `open` — `reference_answer` и пункты `rubric`; для `cloze` — первые элементы `accepted`; для `order` — порядок `steps`; для `find_error` — строки `error_lines` и `line_explanations`. Значения: `yes` (цитата прямо это утверждает), `partial` (подтверждает только часть или нужен вывод, которого в цитате нет), `no`.
2. `second_correct_option`: может ли быть верным ещё что-то, кроме эталона? Для `mcq` — есть ли среди неверных опций такая, которую знающий человек справедливо выберет. Для `cloze` — есть ли очевидный правильный ответ, которого нет в `accepted`. Для `order` — допустим ли другой порядок. Для `find_error` — есть ли ошибка в строке, не указанной в `error_lines`. Для `flip` и `open` — `n/a`. Значения: `yes`, `no`, `n/a`.
3. `unambiguous`: однозначна ли формулировка вопроса для человека, который знает факт? `yes` или `no`.
4. `issues`: короткие конкретные замечания на языке колоды (пустой массив, если их нет). Каждое замечание называет проблемное место (например, опцию `c`, пропуск `{{2}}`, строку 4).

**Для каждого знания дополнительно:** не противоречат ли `fact`, `explanation_short` и `explanation_long` цитатам и нет ли в них утверждений, которые цитаты не покрывают (`unsupported_claims` — список таких утверждений, дословно из колоды).

**Вердикт знания** (`verdict`):
- `ok` — у всех вопросов `quote_supports_answer = yes`, `second_correct_option ∈ {no, n/a}`, `unambiguous = yes`, и `unsupported_claims` пуст;
- `needs_fix` — во всех остальных случаях.

Не исправляй контент и не предлагай переписанные вопросы целиком: только замечания.

**Выход:** только один JSON-объект, без markdown-обёртки и без текста до или после, строго такого вида:

```json
{
  "deck_id": "<deck.id>",
  "deck_version": 1,
  "items": [
    {
      "item_id": "<items[].id>",
      "verdict": "ok",
      "unsupported_claims": [],
      "questions": [
        {
          "question_id": "<questions[].id>",
          "type": "mcq",
          "quote_supports_answer": "yes",
          "second_correct_option": "no",
          "unambiguous": "yes",
          "issues": []
        }
      ]
    }
  ],
  "summary": { "items_total": 0, "items_ok": 0, "items_needs_fix": 0 }
}
```

Правила формата:
- `items` перечисляет **все** знания колоды в исходном порядке, `questions` — все вопросы знания в исходном порядке.
- Перечислимые поля принимают только указанные значения; лишних полей нет.
- `summary` согласован с `items`.

## Как куратор использует отчёт

1. Сохранить ответ в `content/reports/<deck>.verify.json` (папка не коммитится, см. `content/PIPELINE.md`, шаг 4).
2. Проверить, что это корректный JSON, и посмотреть знания с `needs_fix`:
   ```
   jq '.items[] | select(.verdict=="needs_fix") | {item_id, unsupported_claims, q: [.questions[] | select(.issues|length>0) | {question_id, issues}]}' content/reports/<deck>.verify.json
   ```
3. Знаниям с `needs_fix` поставить `review.status = "needs_fix"` и `review.notes` с кратким пересказом замечаний; вычитывать их особенно внимательно (шаг 5).
