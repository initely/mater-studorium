# Mater Studorium

Приложение для регулярного вспоминания знаний (FSRS, разные форматы вопросов, асинхронные дуэли).
ТЗ: [`docs/TZ.md`](docs/TZ.md). Задачи: [`docs/tasks/README.md`](docs/tasks/README.md). Правила проекта: [`CLAUDE.md`](CLAUDE.md).

## Как поднять бэкенд локально

Нужны Docker и [Supabase CLI](https://supabase.com/docs/guides/local-development/cli/getting-started).

```sh
supabase start        # поднимает Postgres, Auth, Studio и др. в Docker, применяет supabase/migrations
supabase status -o env   # адреса и ключи (нужны API_URL и ANON_KEY)
supabase test db      # pgTAP-тесты RLS (supabase/tests)
supabase db reset     # пересоздать БД с нуля по миграциям
supabase stop         # остановить
```

Studio: <http://127.0.0.1:54323> (Authentication → Users, Table Editor → `profiles`).

Анонимный вход включён в `supabase/config.toml` (`[auth] enable_anonymous_sign_ins = true`).
Проверить вручную без приложения:

```sh
curl -s -X POST http://127.0.0.1:54321/auth/v1/signup \
  -H "apikey: <ANON_KEY>" -H "Content-Type: application/json" -d '{}'
```

В ответе будет пользователь с `is_anonymous: true`; триггер создаст ему строку в `public.profiles`.

### Запуск приложения

Скопируй `.env.example` в `.env.json` (файл в `.gitignore`) и впиши `ANON_KEY` из `supabase status -o env`.
Для Android-эмулятора вместо `127.0.0.1` нужен `http://10.0.2.2:54321` (на Android не проверялось; возможно, для http понадобится `usesCleartextTraffic` в debug-манифесте).

```sh
flutter run -d chrome --dart-define-from-file=.env.json
```

Без `.env.json` приложение запустится, но без бэкенда (анонимный вход не выполняется).
Без сети вход повторяется в фоне, пользователю ошибка не показывается.

В клиент попадают только `SUPABASE_URL` и `SUPABASE_ANON_KEY`. Service role и другие секреты в `.env.json` не кладём.

### Колоды: импорт и каталог

Колода хранится в Storage (bucket `decks`, файл `<id>/v<version>.json`), метаданные — в таблице `decks`. Читать их могут все вошедшие пользователи (в том числе анонимные), писать — только service role.

```sh
# .env в корне (не коммитится): URL проекта и ключ service role из `supabase status -o env`
printf 'SUPABASE_URL=http://127.0.0.1:54321\nSUPABASE_SERVICE_ROLE_KEY=<SERVICE_ROLE_KEY>\n' > .env
dart run tools/import_deck.dart content/decks/sample.json --allow-draft   # draft: только в локальный стек
```

Правила импорта (версия, коллизии `item_id`, запрет `--allow-draft` вне локального стека): [`content/PIPELINE.md`](content/PIPELINE.md), шаг 7. В приложении: Главная → «Колоды» → «Скачать».

Ручная проверка (web, Android; в окружении разработки не выполнялась):
1. `supabase start && supabase db reset`, импорт `sample.json` как выше.
2. `flutter run -d chrome --dart-define-from-file=.env.json` (для Android-эмулятора URL `http://10.0.2.2:54321`).
3. Главная → «Колоды»: «Пример колоды…» с кнопкой «Скачать». Нажать: кнопка «Загрузка…», затем «Скачано».
4. Остановить Supabase (`supabase stop`), открыть «Колоды» заново: сообщение «нужна сеть», скачанная колода в списке.
5. Поднять версию: `"version": 2` в копии `sample.json`, импорт с `--allow-draft`, потянуть список вниз: «Обновить» → «Скачано».
6. AC2.1 на Android: колода на 500 знаний (сгенерировать копированием знаний) скачивается и распаковывается быстрее 3 с.

### Сессия: ручной прогон на `sample.json`

Нужен тот же локальный стек и скачанная колода (шаги 1–3 выше); новый код для получения колоды не нужен. В окружении разработки не выполнялся (нет браузера и устройства): логика покрыта widget-тестами, внешний вид и жесты за человеком.
1. Главная → «Начать сессию». Вверху тонкий прогресс-бар времени, «Вопрос 1 из 2», «Осталось 5:00»; таймер идёт.
2. Вопросы: `mcq` про XSS (тап по варианту сразу отвечает; варианты и «Верно»/«Неверно»/«Верный ответ» подписаны не только цветом) и `flip` про HSTS («Показать ответ», затем оценка Снова/Трудно/Хорошо/Легко). `cloze`, `order`, `open`, `find_error` из `sample.json` пока пропускаются (нет модулей, ADR-25).
3. После ответа: вердикт, панель оценки с подсвеченной («предложено»). «Дальше» принимает её, тап по другой кнопке ставит её. У `flip` подсказки нет.
4. Повернуть экран посреди вопроса: выбор и вердикт остались, номер вопроса прежний.
5. Крестик (или «назад») посреди сессии: диалог «Выйти из сессии?»; после выхода ответы остаются (повторный старт не показывает уже отвеченные знания).
6. Разбор (T14): после ответа ниже панели оценки две свёрнутые кнопки «Коротко» и «Подробнее». «Коротко» показывает 2–3 предложения, «Подробнее» — текст с форматированием и «Источники» (название, лицензия, цитата, адрес). «Открыть источник» открывает страницу в новой вкладке (web) или во внешнем браузере (Android); сессия при этом не двигается. Оценка и «Дальше» работают и при открытом, и при закрытом разборе.
7. После последнего вопроса — итоги: «Повторено: 2», «Верно», «Неверно», «По самооценке», «Время», блок «Скоро повторить» (ближайшие повторения), кнопки «Ещё 5 минут» (новая сессия) и «На главную». Если после этого повторять нечего: «Всё повторено 🎉 Следующее повторение — через …».

### Онбординг, главный, колода, настройки: ручной прогон (T18)

В окружении разработки не выполнялся (нет браузера и устройства): логика покрыта widget-тестами, внешний вид, жесты и тап-цели на живом устройстве за человеком. Нужен локальный стек и `sample.json` в каталоге (шаги 1–3 выше).
1. Чистая установка (на web очистить данные сайта): первый кадр без мигания, сразу онбординг «Шаг 1 из 3». «Далее», «Назад», «Пропустить» работают; на шаге 3 «Скачать» у колоды, затем «Начать первую сессию».
2. Сессия открывается поверх главного; пройти оба вопроса, итоги, «На главную»: счётчики пересчитаны, при отсутствии новых и повторений «Всё повторено 🎉» и время следующего.
3. Закрыть и открыть приложение: онбординга нет. Без сети при пустой БД онбординг показывает ошибку каталога и «Повторить», «Выбрать колоду позже» ведёт на главный с призывом скачать.
4. Главный → «Колоды» → тап по скачанной колоде: описание, версия, прогресс (новые / изучаемые / выученные, значок и подпись у каждой строки), «Начать по этой колоде» берёт только знания этой колоды, «Проверить обновление», «−»/«+» лимита новых.
5. «Удалить с устройства»: диалог, «Отмена» ничего не меняет; «Удалить» возвращает в каталог, колода снова «Скачать»; после повторного скачивания прогресс на месте (ADR-27).
6. Настройки: новых в день и размер сессии меняются и переживают перезапуск; при 0 новых на главном «Взять 5 новых».
7. Крупный шрифт (200%), TalkBack: счётчики озвучиваются одной строкой, кнопки «−»/«+» названы.

### Синхронизация: ручной прогон (T17)

Шаги «авиарежим → 20 ответов → сеть» (AC8.1) и «два устройства» (AC8.2). Устройство на web — вкладка Chrome, второе устройство — второй профиль Chrome или Android; для AC8.2 оба должны быть одним аккаунтом: привязка Google (T21, шаги ниже) делает это возможным; без ключей AC8.2 проверяется тестами (`test/core/sync`, `test/integration/sync_live_test.dart`).
1. `supabase start && supabase db reset`, импорт `sample.json`, запуск приложения, онбординг со скачиванием колоды.
2. Выключить сеть (DevTools → Network → Offline или `supabase stop`) и пройти несколько сессий (20 ответов; для одной колоды `sample.json` понадобятся «Взять 5 новых» и повторения по времени). Ошибок о сети нет.
3. Включить сеть (`supabase start`). В течение ~5 с … 5 мин (повтор с нарастающей паузой) или сразу после следующей сессии / возврата во вкладку: в Studio → Table Editor → `review_logs` ровно столько строк, сколько ответов, `user_item_state` — по строке на знание; повторный прогон число строк не меняет.

### Жалобы и «не согласен»: ручной прогон (T20)

Логика покрыта pgTAP, unit-, интеграционными и widget-тестами (в том числе на живом локальном Supabase); экран не просматривался глазами. Нужны `supabase start`, `supabase db reset`, колода `sample.json` в Storage (`tools/import_deck.dart … --allow-draft`), сборка с `--dart-define-from-file=.env.json`. Для «два пользователя» второй профиль Chrome (отдельный анонимный аккаунт) или Android.
1. Пройти вопрос, в разборе нажать «Пожаловаться»: шторка с пятью причинами и комментарием, «Отправить» выключена, пока причина не выбрана; после отправки снэкбар «Спасибо…», кнопка стала «Жалоба отправлена», вопрос в следующих сессиях не показывается (сразу, без сети: выключить сеть до жалобы). Сеть вернулась: в Studio → Table Editor → `reports` строка с `status = new`, `question_text` и версией колоды (AC11.1).
2. Серверное скрытие (ADR-33, п. 4) требует «дорогих» голосов: два **разных** пользователя, обоим аккаунту больше 24 ч на момент жалобы и оба отвечали на этот вопрос (`review_logs`), автоскрытий не больше 20 одновременно. Для ручной проверки состарить аккаунты: Studio → SQL editor, `update auth.users set created_at = now() - interval '30 days' where id in ('<id1>','<id2>');` (id — в `reports.user_id`), затем второй профиль жалуется на тот же вопрос; после синка (~5 с … 5 мин или конец сессии) вопрос скрыт и у третьего пользователя, который не жаловался. Свежие аккаунты ничего не скрывают, пока куратор не поставит `accepted`: `update public.reports set status = 'accepted' where question_id = '<id>';` скрывает вопрос сам по себе.
3. Куратор (AC11.2): Studio → SQL editor, `select * from public.reports_inbox;` (или Table Editor → `reports_inbox`): колода, версия, вопрос, текст вопроса, число жалоб по причинам, `reporters`, `flagged`, последние комментарии. Вернуть вопрос: `update public.reports set status = 'rejected' where question_id = '<id>';` (или `fixed` после правки колоды) — после следующего синка вопрос снова показывается у пользователей, которые на него сами не жаловались.
4. `open`-вопрос с вердиктом ИИ: «Не согласен с оценкой» под вердиктом, в шторке выбрать свою оценку (предложенной ИИ среди вариантов нет), «Отправить и продолжить»: следующий вопрос, в `review_logs` `grade_source = override`, в `reports` строка `grading_disagree` с `answer_text`, `llm_verdict`, `llm_score`, `user_rating`; вопрос не скрыт.
5. Лимит 30 жалоб в сутки на пользователя и гонка параллельных сессий: `tools/reports_limit_race.sh` — ожидается `OK` (ровно 30 из 45); `tools/reports_limit_race.sh --without-lock` временно убирает блокировку пользователя из `public.submit_report` и показывает `LOST` (превышение лимита), затем восстанавливает функцию (ADR-33).
6. Хранение (ручная процедура куратора, не автоматизируется, ADR-33): копии ответов из «не согласен» после решения можно чистить: `delete from public.reports where reason = 'grading_disagree' and status in ('rejected', 'fixed') and created_at < now() - interval '180 days';` (Studio → SQL editor). Об этом сказать в тексте приватности (T18, T26).
7. TalkBack и крупный шрифт (200%): «Пожаловаться» и «Не согласен с оценкой» озвучиваются, причины читаются как переключатели (радио), тап-цели не меньше 48 dp, шторка прокручивается при клавиатуре.

### Напоминания: ручной прогон на Android (T19)

В окружении разработки не выполнялся (нет устройства и эмулятора): логика покрыта unit- и widget-тестами с подменённым планировщиком, реальная доставка уведомлений за человеком. Нужна сборка `flutter run -d <android>` с колодой `sample.json` (шаги 1–3 выше).
1. Настройки → «Ежедневное напоминание» включить. На Android 13+ появляется системный диалог разрешения; на Android 12 и ниже диалога нет. Установить время на +2 минуты при наличии повторений (после ответов в сессии подождать, пока знание станет просроченным, либо изменить время на устройстве). Свернуть приложение, заблокировать экран: уведомление «Пора повторить» приходит в выбранное время, но не точно: допустима задержка до нескольких минут (неточные будильники, ADR-29). Тап по нему открывает сессию, «назад» ведёт на главный. Повторить при закрытом (смахнутом) приложении: тап открывает сессию при холодном старте.
2. Doze: выключить экран, не трогать устройство 30+ минут (или `adb shell dumpsys deviceidle force-idle`), время напоминания внутри этого окна: уведомление приходит, возможно с задержкой до окна обслуживания. На устройствах Xiaomi, Huawei, Samsung с агрессивной экономией проверить в «Автозапуск» и «Без ограничений для батареи» (dontkillmyapp.com).
3. Перезагрузка: поставить напоминание на +5 минут, перезагрузить устройство, не открывая приложение: уведомление всё равно приходит.
4. Отказ в разрешении: «Не разрешать» в диалоге. Тумблер остаётся включённым, под ним пояснение и «Открыть настройки уведомлений», ошибок и всплывающих сообщений нет. Дать разрешение в системных настройках и вернуться в приложение: напоминание заработало без повторного включения. Проверить также повторный отказ (Android больше не показывает диалог) и отключение уведомлений приложения в системе.
5. Не напоминать зря: пройти все просроченные знания в сессии до времени напоминания (запланированные срабатывания видны в `adb shell dumpsys alarm`, фильтр по `mater_studorium`): сегодняшнего срабатывания нет, завтрашние есть, только если к ним что-то будет просрочено. Без колод и без просроченных знаний уведомлений нет.
6. Часовой пояс и лето: сменить пояс в системе, открыть приложение: расписание пересчитано (в `dumpsys alarm` новые моменты). Если приложение не открывать, уведомление придёт по старому моменту (ограничение ADR-29).
7. Онбординг: чистая установка на Android: третий шаг «Напоминание» с тумблером (по умолчанию выключен) и временем; на web онбординг из трёх шагов, в настройках тумблер недоступен с пояснением.
8. Выбор времени: диалог времени, 24-часовой формат; TalkBack: тумблер и строка времени озвучиваются, тап-цели не меньше 48 dp.

### Открытый ответ и диктовка: ручной прогон (T16)

В окружении разработки не выполнялся (нет устройства, Supabase и OpenRouter не запускались): логика покрыта unit- и widget-тестами с фейками и подменённым HTTP; реальная цепочка и диктовка за человеком. Нужны запущенный `supabase start`, `supabase functions serve grade-open-answer --env-file <env с OPENROUTER_API_KEY>`, колода `sample.json` в Storage (`tools/import_deck.dart … --allow-draft`) и сборка с `--dart-define-from-file=.env.json` (шаги выше и в `supabase/functions/grade-open-answer/README.md`). Вопрос `open` показывается у знания со стабильностью от 3 дней: пройти `infosec.xss.reflected` в сессии несколько раз (или выставить в drift `stability`).
1. Текст: ввести ответ, «Проверить». Первый раз диалог «Проверка ответов моделью» → «Разрешить»; скелетон «Проверяю…», вердикт, пункты рубрики (✓ ½ ✗), «что упущено» (тексты с сервера), комментарий, эталон, «Осталось проверок на сегодня: N». Тот же ответ второй раз приходит быстро (кэш, `cached: true` в логе функции). Лог в `review_logs`: `grade_source = llm`, `llm_score`, `answer_text`.
2. Сбои: авиарежим перед «Проверить» (сообщение, эталон, «Проверить ещё раз», «Оценить самому»; после возврата сети повтор работает); остановить функцию (то же); исчерпать лимит (30 оценок за UTC-сутки: ответить 31 раз разными текстами или временно `GRADING_DAILY_LIMIT=1`): сообщение с временем сброса и сразу панель оценки; выйти из аккаунта/удалить сессию: «нужно войти». Во всех случаях `grade_source = self`, сессия не блокируется. Диалог «Без ИИ» и переключатель в настройках: ответ не уходит (проверить по логу функции).
3. Двойной тап по «Проверить» на медленной сети: в логе функции один запрос. Повернуть телефон во время проверки и свернуть/развернуть приложение: текст на месте, результат приходит.
4. Диктовка на Android (русский язык устройства и распознавания): тап по микрофону, системный диалог разрешения; текст появляется в поле по ходу речи; «Закончить» (стоп) и «Отменить диктовку» (текст как до неё); правка перед «Проверить»; режим `voice` в логе функции (поле `input_mode` в запросе видно при `supabase functions serve --debug` или в Network web). Отказ в разрешении («Не разрешать»): пояснение и «Открыть настройки приложения» ведёт на экран приложения; включить микрофон, вернуться: диктовка работает. Молчать 5–10 с: «Речь не расслышали». Режим полёта без офлайн-пакета: «нужна сеть». Свернуть приложение во время диктовки: диктовка закончилась, текст остался.
5. Диктовка в Chrome (десктоп и Android): то же без кнопки настроек (пояснение про браузер); в Firefox/Safari микрофон выключен с пояснением, текстовый ввод работает; сайт открыт по `http://localhost` или `https` (иначе Web Speech не получит микрофон).
6. **R10:** надиктовать 20 терминов («XSS», «CSRF», «SQL-инъекция», «nmap», «HSTS», «TLS», «хеш с солью» …) как ответы или части ответов, посчитать, сколько распознано верно, и сколько оценок модели осталось верными несмотря на ошибки распознавания (ревью T15, п. 13: не слишком ли лояльна оценка `voice`); результат записать в ТЗ §10, строка R10.
7. TalkBack: микрофон, «Проверить», «Не помню», пункты рубрики (озвучиваются «раскрыт/частично/не раскрыт»), сообщения о состоянии (живые области).

Гонка курсора синхронизации (две транзакции одного пользователя и pull между ними; pgTAP так не умеет): при запущенном `supabase start` выполнить `tools/sync_seq_race.sh` — ожидается `OK`; `tools/sync_seq_race.sh --without-lock` временно убирает advisory-блокировку из `private.sync_stamp` и показывает `LOST` (строка не попала ни в один pull), затем восстанавливает функцию (ADR-30).

Тесты каталога, синхронизации и жалоб против живого локального Supabase (по умолчанию пропускаются; `-j 1`, чтобы они не мешали друг другу в общей БД):
```sh
LIVE_SUPABASE_URL=<API_URL> LIVE_SUPABASE_ANON_KEY=<ANON_KEY> LIVE_SUPABASE_SERVICE_KEY=<SERVICE_ROLE_KEY> \
  flutter test --tags live -j 1 test/integration
```

### Привязка Google (T21): настройка и ручная проверка AC1.2

Код, конфиг и тесты готовы, но **ключей Google в репозитории нет и не будет**: их нужно создать самим и подставить по шагам ниже. Без ключей кнопка «Привязать Google» в Настройках → «Аккаунт» показывает «Привязка Google не настроена в этой сборке», приложение не падает, анонимный вход и синхронизация работают как раньше. Решения и компромиссы — ADR-34 в `docs/TZ.md`.

**Как это работает.** Вход через браузер (OAuth, PKCE), без нового пакета: клиент просит у Supabase адрес входа (`linkIdentity` для привязки, обычный `signInWithOAuth` для входа в существующий аккаунт), открывает его во внешнем браузере; после Google пользователь возвращается в приложение (web: на адрес приложения, Android: deep link `app.materstudorium.mater-studorium://login-callback`). Адрес возврата Android — `app.materstudorium.mater-studorium://login-callback` (в схеме нельзя `_`, поэтому applicationId с `-`). Приложение принимает возврат только по этому адресу и только с `code` или ошибкой; ссылки с готовыми токенами (`access_token`, `refresh_token`) отбрасываются (ADR-34, п. 7). Client id и secret Google знает только сервер Supabase, в приложение они не передаются: в клиенте по-прежнему только `SUPABASE_URL` и `SUPABASE_ANON_KEY`. Нужен только **Web client** Google; Android client и SHA-1 для этого способа не нужны.

#### 1. Google Cloud Console

1. <https://console.cloud.google.com> → создать проект (или выбрать существующий).
2. **APIs & Services → OAuth consent screen** (в новом интерфейсе: Google Auth Platform → Branding и Audience): тип *External*; название приложения, почта поддержки; области (scopes) только `openid`, `email`, `profile` (они «не чувствительные», проверка Google не нужна). Пока статус *Testing*, войти смогут только добавленные в **Test users** аккаунты: добавьте свои Google-аккаунты (для проверки AC1.2 нужен один аккаунт, а лучше два). Чтобы пускать всех, нажать *Publish app*.
3. **APIs & Services → Credentials → Create credentials → OAuth client ID**, тип **Web application**. В **Authorized redirect URIs** добавить:
   - локальный Supabase: `http://127.0.0.1:54321/auth/v1/callback`;
   - облачный проект: `https://<project-ref>.supabase.co/auth/v1/callback` (Dashboard → Project Settings → API → Project URL).
   *Authorized JavaScript origins* не нужны (вход идёт через сервер Supabase). Скопировать **Client ID** и **Client secret**.
4. (Не нужно сейчас, на случай перехода на нативный вход, ADR-34.) SHA-1 отладочного ключа Android: `keytool -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android -keypass android` или `cd android && ./gradlew signingReport`; пакет `app.materstudorium.mater_studorium`.

#### 2. Локальный Supabase

1. Скопировать `supabase/.env.example` в `supabase/.env` (он в `.gitignore`, в репозиторий не попадает) и подставить значения:
   ```
   SUPABASE_AUTH_EXTERNAL_GOOGLE_CLIENT_ID=<Client ID из шага 1.3>
   SUPABASE_AUTH_EXTERNAL_GOOGLE_SECRET=<Client secret из шага 1.3>
   ```
2. В `supabase/config.toml` в блоке `[auth.external.google]` поставить `enabled = true` (локально; закоммитите, только когда ключи есть и у остальных разработчиков/CI). `enable_manual_linking = true`, `additional_redirect_urls` (web на порту 3000 и deep link Android) и `[auth.email] enable_signup = false` уже заданы.
3. `supabase stop && supabase start` (переменные читаются при старте). Проверка: `curl -s http://127.0.0.1:54321/auth/v1/settings -H "apikey: <ANON_KEY>"` → `"google":true`.

#### 3. Облачный проект Supabase

1. Dashboard → **Authentication → Sign In / Providers → Google**: включить, вставить Client ID и Client secret (секреты хранятся в Dashboard, в git их нет). Если конфиг применяется через CLI (`supabase config push`), задать те же две переменные в окружении запуска.
2. **Authentication → Sign In / Providers**: *Allow anonymous sign-ins* включено (уже), **Allow manual linking** включить (иначе привязка даёт `manual_linking_disabled`, клиент покажет «не настроено»).
3. **Confirm email** (Authentication → Sign In / Providers → Email) **не выключать** и не выключать через `supabase config push`: в `config.toml` стоит `[auth.email] enable_confirmations = true`. Иначе любой аноним через `PUT /auth/v1/user` мгновенно получает чужую «подтверждённую» почту и перестаёт быть анонимным (заготовка захвата аккаунта через автопривязку по почте, ревью T21, S2). Вход по email в приложении не используется, `enable_signup = false` для email остаётся.
4. **Authentication → URL Configuration → Redirect URLs**: добавить адрес сайта приложения (например `https://<user>.github.io/<repo>/`) и `app.materstudorium.mater-studorium://login-callback`. Site URL — адрес сайта. GoTrue пропускает адрес возврата с тем же хостом, что `site_url`: на общем `<user>.github.io` возврат может принимать любая страница с общим origin, поэтому для публичного релиза лучше отдельный домен для web-клиента (ревью T21, N6).

#### 4. Запуск клиента

В `.env.json` по-прежнему только `SUPABASE_URL` и `SUPABASE_ANON_KEY` (из локального или облачного проекта). Web локально обязательно на порту 3000 (он в списке разрешённых адресов):
```sh
flutter run -d chrome --web-port=3000 --dart-define-from-file=.env.json
```
Android (`flutter run -d <устройство>`): надёжнее всего проверять против **облачного** проекта (https; Google не пускает на `http://10.0.2.2`, а возврат в браузере с телефона на `127.0.0.1` ведёт на сам телефон). С локальным Supabase на реальном телефоне: `adb reverse tcp:54321 tcp:54321` и `SUPABASE_URL=http://127.0.0.1:54321` (не проверялось: Android может блокировать http-трафик в debug-сборке, см. «Запуск приложения»).

#### 5. Ручная проверка AC1.2 (Android + web или два профиля Chrome)

Подготовка: два устройства с разными анонимными аккаунтами: A (например, Chrome, колода `sample.json`) и B (Android или второй профиль Chrome).
1. **A:** пройти сессию (5–10 ответов), дождаться синка (или завершить сессию). Настройки → «Аккаунт»: «Анонимный аккаунт», кнопка «Привязать Google».
2. **A:** «Привязать Google» → страница Google → выбрать аккаунт → разрешить. Возврат в приложение: открываются Настройки, «Google: ваша.почта@…», сообщение «Google привязан. Прогресс сохранён.». В Studio → Authentication → Users: тот же `id`, `is_anonymous = false`, provider `google`; `user_item_state` на месте. Синк продолжает работать (новый ответ доходит до сервера под тем же `user_id`).
3. **B** (свежая установка или очищенные данные сайта): при желании пройти пару вопросов (это локальный прогресс, который будет объединён). Настройки → «Привязать Google» → **тот же** Google-аккаунт → возврат с диалогом «Этот Google уже используется» (текст про объединение по более позднему результату). **Отказаться:** ничего не меняется, B остаётся анонимным. Повторить и нажать **«Войти и объединить»** → Google → возврат: «Google: …», сообщение «Вы вошли в существующий аккаунт Google…».
4. **AC1.2:** после синка (до 5 мин, или завершить сессию) на B видны те же знания, что на A (главный экран: счётчик «к повторению», колода скачана/прогресс; Studio: `select user_id, item_id, reps, updated_at from public.user_item_state where user_id = '<id Google-пользователя>';` — строки A и B, по знанию более поздняя).
5. Отмена: в Google нажать «Отмена»: «Вход отменён. Ничего не изменилось», кнопка снова доступна. Нет сети при нажатии: «Нет связи с сервером…».
6. TalkBack и крупный шрифт: «Аккаунт» озвучивается как заголовок, кнопка и кнопки диалога не меньше 48 dp.

Если с нажатия «Войти и объединить» до возврата прошло больше 15 минут (или вход шёл без подтверждения), приложение честно пишет «Подтверждение устарело, поэтому прогресс этого устройства не перенесён…» и показывает кнопку «Перенести прогресс» (нажатие и есть подтверждение); слов «объединён» в этом случае нет. Проверить: после «Войти и объединить» выждать 16 минут в браузере на странице Google, затем завершить вход.

Что должен увидеть ревьюер: пока не нажато «Войти и объединить», локальный прогресс анонимного A остаётся под его `user_id` (в `supabase` под Google-аккаунт ничего не уходит); после подтверждения он переходит на Google-аккаунт и уходит туда одним синком.

#### 6. Как вернуть всё назад

Убрать `supabase/.env`, в `config.toml` вернуть `enabled = false` для Google, `supabase stop && supabase start` (пользователей в локальной БД сбросит `supabase db reset`). В Google Cloud Console удалить OAuth client. В Studio → Authentication → Users удалить тестового Google-пользователя; в приложении очистить данные (Android: «Хранилище → Очистить данные»; web: «Параметры сайта → Удалить данные»).

#### 7. Если не работает

- «Привязка Google не настроена в этой сборке»: провайдер выключен (`enabled = false`, нет ключей) или выключено ручное связывание. Проверить `.../auth/v1/settings` и «Allow manual linking».
- Google: `redirect_uri_mismatch`: в Authorized redirect URIs нет точного `…/auth/v1/callback` вашего проекта.
- После Google попадаете не в приложение, а на `site_url`: адрес возврата не в списке `additional_redirect_urls` (web: порт 3000; Android: `app.materstudorium.mater-studorium://login-callback`).
- Android: браузер после Google не возвращает в приложение: проверить `intent-filter` в `AndroidManifest.xml` и что приложение установлено как `app.materstudorium.mater_studorium`.
- «Access blocked: app has not completed verification»: аккаунт не в Test users (шаг 1.2).

#### Чистка сиротских анонимов (ревью T04)

Анонимные пользователи, которые давно не заходили и ничего не записали, копятся в `auth.users`. Раз в месяц куратор запускает чистку вручную (Studio → SQL editor или `psql` под `postgres`; `pg_cron` не нужен). Удаляются только анонимы старше 30 дней, без identity, без недавней сессии и **без единой строки** ни в одной таблице с `user_id`/`owner_id` (список берётся из каталога БД; `profiles` уходит каскадом):
```sql
-- посмотреть, кого удалят (по умолчанию пробный запуск, ничего не удаляет)
select * from private.purge_orphan_anonymous_users();
-- удалить (возраст не меньше 7 дней, по умолчанию 30)
select * from private.purge_orphan_anonymous_users(interval '30 days', false);
```
Функция лежит в схеме `private` (через API не вызывается), `execute` только у `service_role` и владельца. Аноним, чей прогресс был перенесён на Google-аккаунт, остаётся на сервере с данными и не удаляется (ADR-34).
