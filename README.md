# Mater Studorium

Приложение для регулярного вспоминания знаний (FSRS, разные форматы вопросов, асинхронные дуэли).
ТЗ: [`docs/TZ.md`](docs/TZ.md). Задачи: [`docs/tasks/README.md`](docs/tasks/README.md). Правила проекта: [`CLAUDE.md`](CLAUDE.md).

## Как поднять бэкенд локально

Нужны Docker и [Supabase CLI](https://supabase.com/docs/guides/local-development/cli/getting-started).

```sh
supabase start        # поднимает Postgres, Auth, Studio и др. в Docker, применяет supabase/migrations
supabase status -o env   # адреса и ключи (нужны API_URL и ANON_KEY)
supabase test db      # pgTAP-тесты RLS (supabase/tests)
supabase db reset     # пересоздать БД с нуля по миграциям
supabase stop         # остановить
```

Studio: <http://127.0.0.1:54323> (Authentication → Users, Table Editor → `profiles`).

Анонимный вход включён в `supabase/config.toml` (`[auth] enable_anonymous_sign_ins = true`).
Проверить вручную без приложения:

```sh
curl -s -X POST http://127.0.0.1:54321/auth/v1/signup \
  -H "apikey: <ANON_KEY>" -H "Content-Type: application/json" -d '{}'
```

В ответе будет пользователь с `is_anonymous: true`; триггер создаст ему строку в `public.profiles`.

### Запуск приложения

Скопируй `.env.example` в `.env.json` (файл в `.gitignore`) и впиши `ANON_KEY` из `supabase status -o env`.
Для Android-эмулятора вместо `127.0.0.1` нужен `http://10.0.2.2:54321` (на Android не проверялось; возможно, для http понадобится `usesCleartextTraffic` в debug-манифесте).

```sh
flutter run -d chrome --dart-define-from-file=.env.json
```

Без `.env.json` приложение запустится, но без бэкенда (анонимный вход не выполняется).
Без сети вход повторяется в фоне, пользователю ошибка не показывается.

В клиент попадают только `SUPABASE_URL` и `SUPABASE_ANON_KEY`. Service role и другие секреты в `.env.json` не кладём.

### Колоды: импорт и каталог

Колода хранится в Storage (bucket `decks`, файл `<id>/v<version>.json`), метаданные — в таблице `decks`. Читать их могут все вошедшие пользователи (в том числе анонимные), писать — только service role.

```sh
# .env в корне (не коммитится): URL проекта и ключ service role из `supabase status -o env`
printf 'SUPABASE_URL=http://127.0.0.1:54321\nSUPABASE_SERVICE_ROLE_KEY=<SERVICE_ROLE_KEY>\n' > .env
dart run tools/import_deck.dart content/decks/sample.json --allow-draft   # draft: только в локальный стек
```

Правила импорта (версия, коллизии `item_id`, запрет `--allow-draft` вне локального стека): [`content/PIPELINE.md`](content/PIPELINE.md), шаг 7. В приложении: Главная → «Колоды» → «Скачать».

Ручная проверка (web, Android; в окружении разработки не выполнялась):
1. `supabase start && supabase db reset`, импорт `sample.json` как выше.
2. `flutter run -d chrome --dart-define-from-file=.env.json` (для Android-эмулятора URL `http://10.0.2.2:54321`).
3. Главная → «Колоды»: «Пример колоды…» с кнопкой «Скачать». Нажать: кнопка «Загрузка…», затем «Скачано».
4. Остановить Supabase (`supabase stop`), открыть «Колоды» заново: сообщение «нужна сеть», скачанная колода в списке.
5. Поднять версию: `"version": 2` в копии `sample.json`, импорт с `--allow-draft`, потянуть список вниз: «Обновить» → «Скачано».
6. AC2.1 на Android: колода на 500 знаний (сгенерировать копированием знаний) скачивается и распаковывается быстрее 3 с.

### Сессия: ручной прогон на `sample.json`

Нужен тот же локальный стек и скачанная колода (шаги 1–3 выше); новый код для получения колоды не нужен. В окружении разработки не выполнялся (нет браузера и устройства): логика покрыта widget-тестами, внешний вид и жесты за человеком.
1. Главная → «Начать сессию». Вверху тонкий прогресс-бар времени, «Вопрос 1 из 2», «Осталось 5:00»; таймер идёт.
2. Вопросы: `mcq` про XSS (тап по варианту сразу отвечает; варианты и «Верно»/«Неверно»/«Верный ответ» подписаны не только цветом) и `flip` про HSTS («Показать ответ», затем оценка Снова/Трудно/Хорошо/Легко). `cloze`, `order`, `open`, `find_error` из `sample.json` пока пропускаются (нет модулей, ADR-25).
3. После ответа: вердикт, панель оценки с подсвеченной («предложено»). «Дальше» принимает её, тап по другой кнопке ставит её. У `flip` подсказки нет.
4. Повернуть экран посреди вопроса: выбор и вердикт остались, номер вопроса прежний.
5. Крестик (или «назад») посреди сессии: диалог «Выйти из сессии?»; после выхода ответы остаются (повторный старт не показывает уже отвеченные знания).
6. Разбор (T14): после ответа ниже панели оценки две свёрнутые кнопки «Коротко» и «Подробнее». «Коротко» показывает 2–3 предложения, «Подробнее» — текст с форматированием и «Источники» (название, лицензия, цитата, адрес). «Открыть источник» открывает страницу в новой вкладке (web) или во внешнем браузере (Android); сессия при этом не двигается. Оценка и «Дальше» работают и при открытом, и при закрытом разборе.
7. После последнего вопроса — итоги: «Повторено: 2», «Верно», «Неверно», «По самооценке», «Время», блок «Скоро повторить» (ближайшие повторения), кнопки «Ещё 5 минут» (новая сессия) и «На главную». Если после этого повторять нечего: «Всё повторено 🎉 Следующее повторение — через …».

Тест каталога против живого локального Supabase (по умолчанию пропускается):
```sh
LIVE_SUPABASE_URL=<API_URL> LIVE_SUPABASE_ANON_KEY=<ANON_KEY> LIVE_SUPABASE_SERVICE_KEY=<SERVICE_ROLE_KEY> \
  flutter test --tags live test/integration
```
